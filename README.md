## 愿景：Human-on-the-loop？

目前 AutoResearch 的困局在于 **“逻辑断层”**：人类研究者的实验逻辑与 AI Vibe Coding 生成的代码逻辑时常分离，甚至完全对不上。AI 喜欢写过度封装的黑盒，人类看不懂也无法修改；而人类脑子里的数学直觉很难清晰的传递给 AI。
更严重的问题在于迭代性，目前没有一个Agent 能帮助人类贯穿完整的实验过程。一个完整的实验过程应该如下
```text
Idea and Hypothesis
        │
        v
编写实验脚本  -> 查看结果  -> 科学发现
        ▲                    │
        │                    │
        └──── 修正假设，继续实验
```

我希望**确认 AI 在科研中的边界**，确立 **Human-on-the-loop** 范式（区别于 Human-in-the-loop）。
 AI 帮助人类快速完成想法验证与迭代。在这个循环中，人类不可缺失，且必须在关键节点（Spec 审查、异常分析）提供高价值的清晰指引。在项目初期人类思路模糊时，AI 提供文献和 Baseline；当思路清晰时，AI 完成代码落地。

## Roadmap

- [ ] Phase 1: 规范与基建 
    - [ ] 1.1 伪代码 Schema 化
    - [ ] 1.2 目录结构与上下文自动化
    初步设想：
    ```text
            Project/
        |-- core/
        |    `-- 存放具体的函数、类的实现，由AI决定如何组织
        |-- experiments/
        |    `-- 此处调用core，组合成单次核心脚本、批量实验脚本与实验的config类的实现
        |-- results/
        |     `-- 此处按照日期存放实验文件，日期内部按照smoke和main区分测试文件和真实文件，每次独立的实验都存放在一个独立的文件夹中
        |-- utils/
        |    `-- 存放一些辅助工具，例如logger的定义等
        |-- docs
        |    `-- 存放伪代码、实验中犯过的错等重要的信息，Agent每次运行前必须全量读取这个文件夹下的内容，这个文件夹的内容主要由人类研究员修订，AI只是辅助。
    ```


- [ ] Phase 2: 调研与项目冷启动
    - [ ] 2.1 AI协助下启发式调研 
    - [ ] 2.2 实验设想转译 (设想 -> 伪代码)
    - [ ] 2.3 V1 代码生成 (设想 + 伪代码 -> 项目第一版)
- [ ] Phase 3: 单次实验执行与与迭代
    - [ ] 3.1 实验 Agent 与 Dry-Run (直觉审查)
    - [ ] 3.2 真实运行与异常捕获
    - [ ] 3.3 知识沉淀 
- [ ] Phase 4 大规模实验、超参优化的脚本
